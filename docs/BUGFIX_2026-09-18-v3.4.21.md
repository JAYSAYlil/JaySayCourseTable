# v3.4.21 拆周定位与周次语义修复

## 用户报告的现象

1. 把一个周次的课程调到另一周次后，课程直接消失。
2. 只调整某一周的课程信息（例如把第 2 周的课从 3-4 节改到 5-6 节）后，该周“调整对了”，但课程信息对不上：
   - 详情页显示的周次变成第 2 周；
   - 其他周的同类课程点进去也显示成第 2 周那一条。

## 根因

1. **定位只认系列，不认具体记录。** 详情页与编辑弹窗都用
   `state.courses.firstOrNull { it.seriesKey == key }` 还原课程。一旦“仅当前周”编辑把课程拆成多条记录
   （`replaceWeek` 会把新记录插在系列首位），任何一周点进去都会命中这第一条记录，
   于是其他周显示的是第 2 周那条（周次＝2、时间＝5-6 节）。日程列表入口同样被强制改成第一条记录。
2. **“取消勾选当前周”被实现成删除。** v3.4.20 为纠正 v3.4.19 的过度纠正，把“仅当前周”范围下的
   取消勾选当作“把课程从这一周移除”。用户的实际意图是“把这一周的课搬到另一周”，
   于是课程被删掉而不是搬走。

## 修复

### 1. 按“系列 + 具体记录”定位

- 详情页、编辑弹窗都新增“具体记录键”（`uniqueKey`）作为首选匹配，找不到时再退化为
  “包含锚点周的那条记录”，最后才是系列首条。
- 记录锚点周：优先当前周；从日程列表等入口进入时用该次课自身的周兜底。
- 日程列表不再把点中的课程替换成系列第一条记录。
- 详情页删除确认、编辑保存也统一使用“正在显示的那一次课所在的周”。

### 2. 周次改动改为“重写整门课程”

新增 `CourseSeriesOperations.applyWeekSelection`：

- 未被勾选的周次从所有记录中移除；
- 仍被勾选的当前周单独使用编辑后的信息；
- 其余周次保留各自原有信息；
- 没有任何记录覆盖的新勾选周次沿用编辑后的信息；
- 勾选没有变化时，结果与原来的 `replaceWeek` 完全一致。

因此“把第 1 周的课调到第 2 周”得到的是位移：课程整体落到第 2 周并带上编辑后的信息，不会消失。

### 3. 语义写清楚

周次属于整门课程，改动必然作用于整个系列；编辑器上方的“应用到全部周”开关只决定
课程信息（时间、教室等）是只改当前这一次课，还是整门课程。周次变动后编辑器会显示该说明。

保留 v3.4.19 的周次校验：清空周次不回填整学期，保存前要求至少选择一个上课周次。

## 回归

- JVM 165 项（新增 4 项 `CourseSeriesOperationsTest`）：无改动时等价于 `replaceWeek`；搬到新周是位移；
  去掉当前周仍保留其他周；周次变化不会把编辑后的信息广播到其他周。
- API 34 UI 72 项（新增 2 项）：仅排在第 1 周的课程改到第 2 周后落盘仍为 `[2]`；
  已拆分的系列在第 3 周点进去显示 `3-4周` 而不是排在最前的第 2 周记录。
- 整套 UI 运行前清空模拟器应用数据；日程列表入口的“滚动后点击落空”误报改为滚动→点击→确认打开。

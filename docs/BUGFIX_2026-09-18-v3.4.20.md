# v3.4.20 课程编辑保存范围修复

## 原因

v3.4.19 为了让“改过的周次”不被当前周保存路径覆盖，在编辑器里用
`applyToAll = form.applyToAll || weeksChanged` 强制把保存范围升级为整组课程，并把开关置灰。
这绕过了用户自己的选择：只要动了周次，整门课的所有周次都会被改写。

## 行为（保存范围由用户开关决定）

- 开关关闭（默认，仅当前周）：
  - 当前周仍在所选周次内 → 只改写当前周这一次课，其他周次不变。
  - 当前周被取消勾选 → 只把该课程从当前周移除（`deleteWeek`），其他周次不变，不触发冲突检测。
  - 其他周次的勾选变化在本范围内不生效；编辑器显示“仅调整本周（第 N 周）；要修改整组课程的周次，请打开上方开关”。
- 开关打开（应用到全部周）：整组课程替换为编辑器中的周次与其它字段（`replaceAll`）。
- 新增课程仍然默认选中全学期，且总是整组保存。

保留 v3.4.19 的有效修复：清空周次不回填整学期，保存前要求至少选择一个上课周次。

## 回归

- `CourseEditorWeeksTest`（7 项）：改动周次后范围仍为当前周、开关保持可用；开关打开后才发送整组范围；范围提示仅在“周次改动 + 仅当前周”时出现；空选跨重建保持空且不可保存；还原周次后开关仍可用；单双周快捷键；新增课程默认全学期。
- `CourseWeeksPersistenceTest`（2 项，真实 Activity + 落盘断言）：仅当前周范围下取消勾选当前周，磁盘上只剩该周被移除；开关打开后取消第 2 周，整组周次持久化为 `[1, 3, 4]`。

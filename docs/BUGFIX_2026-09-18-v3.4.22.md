# v3.4.22 “这一次课”保存语义与导入按课名同一门课

## 用户要的规则（原话整理）

- 课程在每一周都是一样的；编辑其中一周的某一门课，只有打开“应用到全部周”时，其它周的同一门课才一起变。
- 不打开“应用到全部周”（默认关闭）时，编辑只对**被编辑的这一周这一次课**有效。
- 例：把某一周的某场课调到另一周的另一组节次 —— 在编辑器里改掉开始/结束节次，周次只勾选目标周即可。
- 周次信息既要显示这门课排在哪些周，也要显示当前编辑的是哪一周。
- 导入识别要能确认“不同周次的同一门课”，按课名归为一门课。

## 之前的偏差

- v3.4.20：把“取消勾选当前周”实现成“从这一周删除”，课程只有这一周时整门课会被删掉（表现为“编辑后课程消失”）。
- v3.4.21：改成“周次一改就重写整组”，又没有把编辑内容带到新周次上：第 1 周改成第 2 周后，第 2 周拿到的是旧节次，用户看到的仍是“没改对/像丢了”。
- 两者都不符合“这一次课”的语义。

## 本次实现

### 1. `CourseSeriesOperations.replaceCurrentWeekInstance`（仅这一次课）

- 周次**没有改动**（勾选与课程现有周次一致）→ 这一次课只覆盖 `week` 这一周，其它周次的记录（周次集合与所有字段）完全不动。
- 周次**被改动**（例如只勾选第 2 周）→ 这一次课整体移动到所选周次，编辑后的字段跟着一起走；其它记录交出这些周次，于是是“位移”，既不删除也不重复。
- 极端情况同样保证课程存在：课程只排在某周时，编辑或搬动都不会把系列清空。

### 2. 编辑器

- “应用到全部周”默认关闭，开关始终由用户控制（不再有强制升级、也不锁死周次）。
- 周次区域同时显示排课周次与“本次编辑：第 N 周”。

### 3. 导入识别与系列归一按课名

- `Course.importIdentityKey` 改为“课名 + 上课星期 + 开始/结束节次”：同一门课在不同周次分行（课程号、教师、教室可能不同）会被识别为同一门课并合并周次。
- `CourseSeriesIds.ensure` 增加归一步骤：同一门课（课名 + 上课时段）无论课程号/教师/教室是否一致，都归入同一系列，使“应用到全部周”能覆盖这门课的全部周次；该步骤幂等。

### 4. 课表管理页删除确认

- 由 Material `AlertDialog` 改为与课程详情删除确认一致的底部抽屉（`AppShapes.sheet` + 整宽主操作 + 次操作），统一材质。

## 回归

- JVM：系列操作新增“只改本周 / 搬周次带上编辑内容 / 只有一周也不丢课 / 同名不同课程号同一系列 / 同名不同周次导入合并”；导入分析新增按课名合并用例。
- API 34 UI：`changingWeeksMovesThisOccurrenceAndCarriesTheEdit`（搬周次后落盘为 `[目标周]` 且名称跟着走）、`editingWithoutTouchingWeeksKeepsTheCourseInThatWeek`（不动周次时课程不消失）、`splitSeriesDetailShowsTheTappedWeekInsteadOfTheFirstRecord`（拆周后详情显示点中的那一周）。

# AI 课表转换页重设计验收方案

## 问题与目标

当前 v3.4.35 页面把隐私说明、首表提示、保存方式和计费说明直接铺成整段正文，文件、供应商、Key、保存、测试和转换的控件也平铺成一列。320×640 屏幕首屏只能看到文件和半个密钥区，缺少课表应用已有的白色分组卡、简洁小标题和明确主操作；保存和连接测试被画得与转换一样重。实测截图位于 `app/build/ai-before.png` 与 `app/build/ai-before-lower.png`（构建目录中的本地证据，不入仓库），对照设置页 `app/build/settings-screen.png`。

目标是沿用设置页、导入确认页的视觉语言，以清楚的三段流程呈现“文件 → AI 服务 → 转换”。只重做布局、文案与视觉层级；**不改** Excel 提取、供应商预设与密钥持久化、连接检测、隐私同意、转换、导出及导入确认逻辑。

## 页面结构

1. 用现有 `AppTopBar` 固定返回与标题，内容独立滚动；容器背景、`AppPanel`、`AppShapes`、主题色和 App 控件与设置页一致。左右统一 16–20dp，分组间距清楚，窄屏和大字体不得裁切。
2. “课表文件”分组：整行点击选 Excel；未选择时显示动作，已选择时清楚显示文件名与可更换操作。关于“只读首个可见工作表／文件大小限制”的提醒压成简短辅助文字，放在文件操作附近，避免开头四五行总说明。
3. “AI 服务”分组：供应商选择做成设置页风格的信息行，右侧显示已选供应商和箭头；默认模型内置，只展示 API Key 输入。自定义 URL、模型修改放在高级设置里（自定义 URL 必须可见）；勾选保存 Key、保存配置与删除 Key 放在相邻位置。保存反馈贴近保存动作；错误与连接状态贴近检测动作。检测连接可取消，固定短消息、不发送课表、可能消耗少量额度的说明保留但精简。
4. “开始转换”分组：把“工作表会发送给当前服务商、结果仍需核对、服务商可能收费”的同意说明压成可读的两行左右，复选框与主按钮相邻。主按钮成为页面唯一高强调操作；准备条件不足时禁用理由可从邻近控件理解。
5. 结果分组：显示课程数量、超出学期周数等风险信息；课程预览用紧凑行排版（课程名优先，其余信息次级），保留已有最多 20 条与“更多”提示，随后是保存模板、进入导入确认。勿把每门课程挤成无层级的长段文字。

## 实施边界与验收

- 保留所有现有 `testTag`（包括文件、供应商、URL、模型、Key、保存、检测、检测状态、同意、转换、取消、结果保存、导入），避免破坏自动化和无障碍入口。
- 用户可见文案放 `strings.xml`；无 Material 默认形态的突兀按钮、堆叠毛玻璃或装饰性动画。高级区展开/收起可使用现有短促、可中断的反馈，但以稳定布局和响应速度优先。
- 验证空文件／未填 Key／未同意的禁用状态，供应商切换与保存状态、测试成功/失败、转换进度与取消、结果预览。至少做 320×640 浅色和深色、较宽设备与大字体布局检查；实测截图保存在忽略目录。
- 根代理负责版本文档、JVM/API34 回归、Lint、Release 构建、兼容签名与本地安装包交付。候选版本 v3.4.36 / versionCode 156，不自动公开发布。

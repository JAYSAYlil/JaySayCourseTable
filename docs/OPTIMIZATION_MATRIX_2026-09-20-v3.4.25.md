# v3.4.25 等价优化记录

## 范围

基线为 v3.4.24（提交 3a70216）。保留已修复的三档编辑范围与调课语义，不添加用户功能、不改变数据格式，不重写持久化与导入逻辑。

## 优化

- `ScheduleDateResolver.Prepared` 在一次批量操作开始时按星期分组课程、按日期分组例外。逐日查询只交给原解析器当天候选集合；未改变日期规则，也未添加全局缓存。
- 日程列表、日历导出和每周提醒计算接入该索引。日历导出的停课周集合改为每次导出建立一次。
- 日程日期天然有序，直接产生日期组并对当天课程排序，移除整学期实例中间列表、全量排序和二次 groupBy。
- 修正 AGENTS.md 中遗留的 v3.4.19 周次规则，使其与用户认可的 v3.4.24 行为一致。

## 验证依据

- PreparedScheduleResolverTest 对比直接查询与索引查询，覆盖非周一学期起点、无效日期、零周/短学期/正常学期、学期前后补课、停课、取消和拆分课程，检查完整结果及顺序。
- 140 门课、140 条日期例外、140 天的计数测试：原输入集合各访问 19600 次；索引构建各访问 140 次，之后查询只扫描各日期/星期子集。该数字反映原始集合访问量，不是总扫描次数或真机加速比例。
- 新建索引反映课程周次修改，不会从全局缓存读取过期结果。

## 回归测试修正

首次完整 UI 回归为 79/80 通过。原有真实样本调课用例假定编辑器只选来源周，但编辑器实际加载该记录全部周次，两个 toggle 操作不能得到“只选目标周”的测试前提。修正用例为先验证原有周次已选中，再取消目标周以外的选项；保留调课结果、来源周移除、目标周原有课程保留的全部断言。未修改课程编辑业务逻辑。

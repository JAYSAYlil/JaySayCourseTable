# v3.4.19 课程周次编辑修复

> 本轮的“周次变更一律整组保存”已在 v3.4.20 撤销（它绕过了用户的保存范围开关）；当前规则见 `docs/BUGFIX_2026-09-18-v3.4.20.md`。

## 原因

1. 编辑器默认 applyToAll=false，MainActivity 的当前周保存路径会用当前周替换所选周次。因此按钮选择虽变化，持久化结果仍不符合用户选择。
2. 旧文本输入规则把空白解释为整学期。切换到点选周次后仍保留这条规则，取消最后一周会立即回填全部周次，保存时也有同样的兜底。

## 行为

- 周次发生变更时，编辑器显示“周次调整应用到整组课程”，保存采用已有的整组替换路径，冲突检测范围与保存范围保持一致。
- 周次恢复原样时，允许继续切换仅当前周/全部周编辑。
- 空选保持空选，包括表单重建后；保存要求至少选择一周。新增课程初始默认全学期不变。
- 包名、数据结构、兼容升级签名不变；versionName=3.4.19，versionCode=139。

## 回归

旧版专项测试分别在保存范围断言和清空后选择状态断言失败，复现了两条故障链。新增测试覆盖修改周次、空选及表单重建、恢复有效选择、还原原周次、单双周快捷按钮、新增默认值和实际 Activity 编辑保存后重开。

修复后全量验证：161 项 JVM 测试通过，API 34 Android UI 测试 69/69 通过，Release Lint 通过。实际保存测试直接读取 CourseRepository 落盘数据，确认取消第 2 周后保存为 [1, 3, 4]，重建 Activity 后重新打开编辑仍保持该选择。

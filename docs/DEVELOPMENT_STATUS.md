## 上一轮（v3.4.31，本地交付：中性框染上主题色＋周次一键清除）

- 当前版本：3.4.31 / versionCode 151。
- 用户反馈"搜索框和上午/下午/晚上那一行的框泛绿"。定位到根因是中性框令牌 `surfaceVariant`：浅色 `#EDEFF0`、深色 `#232628` 自带冷绿偏移，且节次分组行另有一份硬编码冷灰（`#F0F1F2`／`#17191B`）。
- 改法：基底换成无色相的 `NeutralField #F2F2F2`／`DarkNeutralField #262626`，再按 `FIELD_TINT_LIGHT 0.45`／`FIELD_TINT_DARK 0.35` 混向该主题色的**容器色**；节次分组行删掉自带底色，改用同一令牌。15 处中性框（搜索框、选项块、分组底）一次全部跟随主题色。
- 为什么用容器色而不是 primary 叠加：同样对比度预算下，容器色混色的可见色相约为 primary 低透明度叠加的两倍（primary 叠加要到 8–10% 才看得出来，但那会把框上文字压到 4.5:1 以下）。
- 对比度实测：框上标签与占位文字（`onSurfaceVariant`）在八套主题色、深浅两端都 ≥4.5:1，浅色最差 4.67、深色最差 5.29，由新增 JVM 用例锁住；另一条用例要求八套色下的中性框两两可辨、且仍比纯白内容面暗。
- 课程编辑的上课周次新增"清除"芯片：与全学期／单周／双周同一行、同样式、同 72×40dp，`selected = selectedWeeks.isEmpty()`，点击 `selectWeeks(emptySet())`；文案入 `strings.xml`（`edit_weeks_clear`）。空选保存仍被 `edit_error_weeks_invalid` 拦下，符合"空选不得回退为全学期"的既有不变量。
- 同类问题复查：业务代码里已无其它固定中性填充（`Color(0x...)` 字面量只剩 1 处主题色选项的勾选墨色，本就该是墨色）；课表与月视图所有强调位都取自 `MaterialTheme.colorScheme.primary`；描边与正文墨色刻意保持无色相，理由：1px 描边跟着染色只会让整页显脏，且这些值此前已按肉眼不可辨的 1–3/255 偏移保留。
- 踩到的坑（记下来避免重复）：① 横向滚动行里的芯片，`performScrollTo()` 之后再去点另一个节点会让目标滚出屏幕（bounds 出现负坐标 x=-247），合成点击静默落空——点击断言留在 `totalWeeks=4` 的 `CourseEditorWeeksTest`，`RevisionVisualTest` 里只做同行/等高布局断言；② `createComposeRule` 的 `setContent` 每个用例只能调用一次，八套主题色要在同一次组合里各套一层 `JaySayTheme` 逐层取回 `ColorScheme`；③ 编辑过程中一次 Edit 误删了"全学期"芯片，靠复查 `git diff` 发现并补回——重签后的 APK SHA-256 与首次签名完全一致，反证最终源码与首次构建逐字节相同。

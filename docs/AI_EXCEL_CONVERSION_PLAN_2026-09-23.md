# 自带 API Key 的 AI 课表转换：实施计划

## 目标与边界

用户从“导入与导出”进入，选择学校导出的 `.xls` / `.xlsx`，填写自己使用的 OpenAI Chat Completions 兼容接口完整 HTTPS 地址、模型名与 API Key。应用在用户明确点击“开始转换”后，才把所选工作簿的有限文本内容发送到该接口。AI 返回的课程先在本地严格校验，用户可以保存为现有 19 列模板格式的 `.xlsx`，也可以进入现有导入确认页选择要导入的课程。任何转换结果都不得未经确认直接写入课表。

第一版支持 Chat Completions 兼容的文本接口，由用户自行选择供应商；不做学校网站登录、爬取或账号代管，不假设所有学校文件一定能正确识别。不能从源文件确定的周次、节次和星期不得由 AI 猜测成确定值；结果需要用户检查。项目根目录的三份真实课表只用于本机格式核对，不入库、不作为在线测试负载。

## 现有约束

- `ExcelParser` 的必要列为课程号、课程名、上课星期、开始节次、结束节次、上课周次；现有 `import_template.xlsx` 有 19 列。保留旧 `.xls` 与 `.xlsx` 导入能力，不引入 POI OOXML。
- `ImportConfirmScreen` / `CourseImportAnalyzer` 已负责重复课程、冲突及用户选择；AI 路径复用它们，不重写入库语义。
- 新页面加入 `Screen` 时只追加枚举项，避免已有序号导航状态错位。保持包名、schemaVersion 4、兼容签名不变。

## 实施顺序（GPT-6 Luna）

1. 建立输入提取器：使用现有 Excel 读取器读取所选文件，转为带行列坐标的有限文本；文件字节、单元格数、行数和请求文本均设上限，超限时给可操作错误，不悄悄截断课程。IO 在线程池进行。
2. 建立接口客户端：只允许 HTTPS，拒绝凭据嵌入 URL、查询参数、重定向与本地/私有地址；请求采用 Chat Completions 的 `model`、`messages`，并使用 Bearer API Key。设置连接/读取超时与响应体大小上限。密钥仅保留在本次界面内存，不放进偏好、日志、异常文案或备份。请求中说明数据会发给用户选择的供应商，发送前必须由用户主动点击。
3. 定义严格的 JSON 课程结果契约：逐条校验课程名、周次、星期、起止节次；可选字段仅接受明确文本或默认空值。课程号缺失时在本地生成稳定的占位编号并在预览中提示，不让模型虚构学校编号。无有效课程、截断响应或无法识别内容均明确报错，不自动导入。
4. 生成现有 19 列模板兼容的 `.xlsx`，使用轻量 OOXML 写入，不增加 POI OOXML 依赖。生成内容须被现有 `ExcelParser` 回读，并在课程关键字段上等价。
5. 在设置页“导入与导出”增加“AI 转换学校课表”入口。选择文件、填写完整 HTTPS 接口地址/模型/API Key、查看传输提示、转换中取消/失败重试、转换结果摘要、保存模板与进入原有导入确认页；新页面遵守现有主题和返回行为。无网络、401/429、格式错误应有不泄露响应正文和密钥的提示。

## 验收

- 纯本地测试覆盖：提取边界、URL 拒绝、恶意/缺项/越界 AI JSON、课程号缺失、周次解析、模板写入后通过现有导入器回读、用户取消后不入库；HTTP 用本地受控假服务或可注入传输层模拟，不用真实 API Key 或真实课表调用外网。
- 项目现有 JVM 测试、API 34 模拟器界面回归、Release Lint/构建、签名兼容与覆盖安装检查通过。UI 测试至少覆盖新入口和“结果需确认”路径。
- 发布前更新版本与文档，按既有本地签名交付方式交付 APK；未经另外明确要求，不推送 GitHub。

接口依据：[OpenAI Chat Completions API](https://platform.openai.com/docs/api-reference/chat/create)、[DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)、[智谱 AI 接口文档](https://docs.bigmodel.cn/cn/best-practice/case/ai-search-engine)。这些文档支持采用用户可配置的兼容接口；具体供应商和模型是否兼容仍须以用户填写的接口及当时服务为准。
